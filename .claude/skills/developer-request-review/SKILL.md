# developer-request-review

GA4 이벤트 구현 요청(기획/PM/마케터 등이 개발자에게 준 요청)을 받았을 때, 개발자 입장에서 구현 전에 빠진 정보가 없는지 검토하는 스킬입니다.

## 언제 쓰는가

- "이 이벤트를 이렇게 구현해줘" 같은 GA4 이벤트 구현 요청을 검토해 달라고 할 때
- 구현에 들어가기 전에 요청서에 빠진 내용이 있는지 확인하고 싶을 때

## 절차

### 1. 요청 내용 정리

받은 요청에서 다음이 이미 명시되어 있는지 확인합니다.

- 이벤트를 발생시키는 행동(트리거) — 예: 어떤 버튼/화면/조건에서 발생하는지
- 이벤트 이름
- 파라미터(속성) 이름과 값, 타입
- 발생 시점 (예: 클릭 즉시 / 응답 성공 후)
- 발생 빈도나 예외 조건 (예: 중복 방지, 로그인 사용자만 등)

**이미 답이 있는 항목은 질문 목록에서 제외**합니다.

### 2. 질문 추리기

위 항목 중 요청에 없어서 구현이 막히거나 모호한 것만 골라, **최대 3개**까지 질문으로 만듭니다. 우선순위:

1. 구현 자체가 불가능한 수준의 누락 (예: 트리거 조건 불명확)
2. 잘못 구현될 위험이 큰 모호함 (예: 파라미터 값의 형식/단위 불명)
3. 있으면 좋지만 없어도 기본값으로 구현 가능한 것

질문이 하나도 없으면 "되물을 내용 없음"이라고 명시합니다. **모르는 내용을 임의로 추측해서 채우지 않습니다.**

### 3. 출력 형식

다음 형식의 마크다운 표로 정리합니다. (질문이 없으면 표 대신 "되물을 내용 없음"이라고만 씁니다.)

```markdown
| 질문 | 답이 필요한 이유 |
|---|---|
| <질문 1> | <이 답이 없으면 왜 구현이 막히거나 잘못될 수 있는지> |
| <질문 2> | ... |
| <질문 3> | ... |
```

### 4. 파일로 저장

검토 결과(질문 표 또는 "되물을 내용 없음")를 마크다운 파일로 저장합니다. 파일명은 `review-<요청을 요약한 kebab-case>.md` 형태로 하고, 저장 위치를 사용자에게 알려줍니다.
